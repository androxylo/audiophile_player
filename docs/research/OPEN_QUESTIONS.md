## 5. Audirvana Kernel Mode, Windows Kernel Streaming & Playback Hygiene (`INV-06` — *Resolved; hardware probe pending POC #1*)

- **OQ-18:** *(Resolved in [06-windows-kernel-streaming.md](06-windows-kernel-streaming.md) §1)* Audirvana's Windows Kernel Streaming uses user-mode WDM-KS (`SetupDi*` → `CreateFile` → `KsCreatePin` → `KSPROPERTY_RTAUDIO_BUFFER_WITH_NOTIFICATION` WaveRT cyclic buffer directly on `usbaudio2.sys`), bypassing both `audiodg.exe` and `AudioSes.dll`. WASAPI Exclusive Mode also bypasses `audiodg.exe` completely and maps the same `usbaudio2.sys` WaveRT buffer via in-process `AudioSes.dll`. We will support **both** zero-mixer transports (never Shared Mode).
- **OQ-19:** *(Resolved & empirically verified on Gungnir 2 in [06-windows-kernel-streaming.md](06-windows-kernel-streaming.md) §1–2, §5)* Both **WDM-KS** and **WASAPI Exclusive** passed **16/16 live hardware stream opens** on Gungnir 2 Unison 384 (`44.1 → 384 kHz`, `int32` & `int16`), including clean `384 kHz / int32` playback with `0` underflows over WDM-KS. WASAPI Exclusive cleanly evicts shared clients (`audiodg.exe`); WDM-KS requires full pin teardown (`KSSTATE_STOP → CloseHandle → KsCreatePin`) on rate switches and fails if `audiodg.exe` holds the pin open.
- **OQ-20:** *(Resolved in [06-windows-kernel-streaming.md](06-windows-kernel-streaming.md) §3)* **Minimal-effort POC #1:** Python (`sounddevice` + `soundfile`, already-installed Python 3.14) gives **both** WASAPI Exclusive and WDM-KS with `dtype='int32', clip_off=True, dither_off=True` in ~100 lines. **POC #2 / Production:** Direct Win32 `IAudioClient` Exclusive + direct `KsCreatePin`/WaveRT WDM-KS (first in C/C++ or directly via Rust `windows-rs`) with zero middleware.
- **OQ-21:** *(Resolved in [06-windows-kernel-streaming.md](06-windows-kernel-streaming.md) §2)* Milestone 1 uses **Full-Memory RAM playback** per track (decode entire FLAC into RAM before streaming; MMCSS `"Pro Audio"` thread; `50–100 ms` hardware buffer; optional `VirtualLock`). Streaming overlap-add ring buffering will be added for Milestone 2 (Tidal).
- **OQ-22:** *(Resolved in [06-windows-kernel-streaming.md](06-windows-kernel-streaming.md) §4)* Four-part verification gate: (1) Exclusive lock test (blocks browser/OS audio), (2) Windows volume/APO immunity check, (3) Dynamic native rate lock with Windows default set to a different rate + `audiodg.exe` 0% activity check, and (4) TDD bit-exact integer frame hash check on synthetic FLAC fixtures.
